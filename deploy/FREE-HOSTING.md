# بداية بخطط مجانية: Render + Supabase

هذا هو مسار النشر المقترح لمن لا يملك سيرفرًا. Render يشغّل Node، وSupabase يخزن قاعدة البيانات والمرفقات. لا تستخدم SQLite أو مجلد `data` على قرص Render المؤقت لحفظ بيانات العملاء.

لا تحتاج نطاقًا مدفوعًا: رابط Render الافتراضي يكفي. راجع الأسعار والشروط أثناء التسجيل قبل اختيار الخطة: قد تتغير الحدود أو متطلبات التحقق، وقد تتوقف خدمة Render المجانية عند الخمول ويتأخر أول طلب، وقد يوقف Supabase مشروعًا مجانيًا غير نشط. لا يوجد ضمان لتشغيل مجاني للأبد. لا تشترك في خطة مدفوعة أو تفعّل ترقية تلقائية إن كنت تريد المجاني فقط.

## ١. حسابا الاستضافة

- أنشئ حسابًا باسمك في https://supabase.com/ وحسابًا في https://render.com/، واختر Free حيث يكون متاحًا. الأفضل ربط Render بحساب GitHub الذي يملك مستودع softTV.
- لا ترسل كلمات مرور الحسابات أو مفاتيح Supabase في المحادثة. أدخلها فقط في إعدادات الاستضافة الآمنة.

## ٢. Supabase

1. أنشئ مشروعًا جديدًا مخصصًا للموقع ضمن الخطة المجانية، وانتظر جاهزيته.
2. افتح SQL Editor وشغّل محتوى `supabase/setup.sql`. ينشئ جدول الطلبات وحاوية مرفقات **خاصة** ويمنع وصول الزوار إلى الجدول مباشرة.
3. من إعدادات المشروع/API احفظ Project URL (مثل `https://PROJECT.supabase.co`) و**service_role key** القديم الخاص بالخادم إن كان متاحًا ضمن API keys/legacy keys. لا تستخدم المفتاح `anon` أو publishable. هذا الإصدار يستعمل service_role JWT في طلبات الخادم فقط؛ لا تضعه في ملفات public أو Git.
4. لا تغيّر الحاوية إلى Public، ولا تضف سياسات عامة تسمح بالقراءة أو الرفع بدون الخادم.

## ٣. GitHub ثم Render

1. ارفع ملفات المشروع إلى مستودعك `BADER-EDDIN-OMAR/softTV` بدون `.env` أو `data` أو النسخ الاحتياطية. ملف `render.yaml` يجب أن يكون في جذر المستودع. لم تُرفع الملفات إلى GitHub تلقائيًا.
2. في Render أنشئ Blueprint من مستودعك مستخدمًا `render.yaml`، أو Web Service بخطة Free، وNode.js 24، وأمر بناء `node --check server.js && node --check storage.js`، وأمر تشغيل `npm start` ومسار فحص `/api/health`.
3. اضبط متغيرات البيئة في Render:

| الاسم | القيمة |
| --- | --- |
| `SUPABASE_URL` | Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key الخاص بالمشروع؛ سر للخادم فقط |
| `ADMIN_PASSWORD` | كلمة مرور قوية من ١٢ حرفًا فأكثر؛ Blueprint يولّدها تلقائيًا ويمكنك قراءتها بأمان من إعدادات Render |
| `APP_ORIGIN` | اختياري على Render؛ يقرأ التطبيق `RENDER_EXTERNAL_URL` تلقائيًا. عند ربط نطاق مخصص اضبطه على أصل نطاقك العام بدون شرطة أخيرة أو مسار |
| `COOKIE_SECURE` | `true` |
| `TRUST_PROXY` | `true` عند الاعتماد على وكيل Render الذي يستبدل عنوان العميل |
| `NODE_VERSION` | `24` |

يقرأ التطبيق رابط Render الافتراضي تلقائيًا. لا تعتبر الموقع جاهزًا إذا فشل فحص الصحة؛ يعكس فحص الصحة الوصول الفعلي لجدول Supabase.

## ٤. فحص النشر الحقيقي

- افتح الموقع وأرسل طلبًا مع صورة. احفظ رقم الطلب ورمز المتابعة.
- ادخل `/admin` بكلمة مرور Render. افتح الصورة وغيّر حالة الطلب وأضف ردًا.
- تابع الطلب من صفحة العملاء وتحقق من الرد.
- أعد تشغيل الخدمة من Render وتحقق من أن الطلب والمرفق ما زالا موجودين. تسجيل دخول الإدارة من جديد بعد إعادة التشغيل متوقع.
- تحقق من أن رابط المرفق لا يُفتح من نافذة خاصة بدون تسجيل دخول.

## حدود البيانات والنسخ الاحتياطي

راقب استهلاك مساحة المرفقات والنقل في Supabase؛ المقاطع تستهلك الحصة بسرعة. التطبيق يرفض المرفقات فوق ١٥ ميجابايت. لا يرقّي الخطط تلقائيًا. أدوات النسخ الاحتياطي المحلية `scripts/backup.sh` تخص نشر Docker/SQLite فقط؛ **لا تنسخ بيانات Supabase**. استخدم تصدير قاعدة البيانات ونسخ الحاوية الخاصة بأدوات Supabase، واحفظ الملفات بأمان خارج المشروع. توافر النسخ الآلي يعتمد على خطة المزود؛ لا تفترض أنه مشمول مجانًا.

## ما تم وما لم يتم اختباره

تم اختبار SQLite محليًا، ومحوّل Supabase باختبارات تحاكي عقد HTTP، وإعادة بناء حزمة Docker بعد إضافة المحوّل. لا تعادل المحاكاة اختبار Supabase الفعلي. لم يتم إنشاء الحسابات أو تشغيل SQL في مشروع حقيقي أو النشر إلى Render أو إصدار رابط عام؛ ذلك يحتاج إعداد الحسابين وإدخال القيم الآمنة أولًا.
