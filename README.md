# SoftTV — بوابة طلبات العملاء

موقع عربي متجاوب لتقديم طلبات إضافة الأفلام والمسلسلات والقنوات والإبلاغ عن مشاكلها، مع مرفقات، متابعة خاصة، ولوحة إدارة محمية. لا يحتاج العميل إلى حساب.

## التشغيل المحلي

يتطلب Node.js 24 أو أحدث. لا توجد حزم خارجية أو عملية بناء.

```sh
cd /workspace/softTV
npm start
```

المنفذ الافتراضي `3000`. صفحة العملاء `/` ولوحة الإدارة `/admin`.

عند التشغيل الأول تُنشأ كلمة مرور عشوائية في `data/admin-password` بصلاحية قراءة خاصة. اقرأها محليًا من هذا الملف؛ لا تنشره ولا تشاركه. يمكنك بدلًا من ذلك ضبط `ADMIN_PASSWORD` (١٢ حرفًا على الأقل) في بيئة التشغيل. تغييره يتطلب إعادة تشغيل الخادم. لا تُطبع كلمة المرور في السجل.

`npm run dev` يعيد تشغيل الخادم عند تعديل الملفات. `npm test` يختبر الإرسال، المرفقات، خصوصية المتابعة، تسجيل الدخول، حماية التحديثات، وبقاء البيانات بعد إعادة التشغيل، باستخدام قاعدة بيانات مؤقتة منفصلة.

## رحلة الاستخدام

- العميل يختار إضافة محتوى أو بلاغ مشكلة، ثم نوع المحتوى واللغة والتفاصيل.
- المرفق اختياري: JPG، PNG، WebP، MP4، WebM حتى ١٥ ميجابايت.
- بعد الإرسال يظهر رقم الطلب ورمز متابعة خاص. يجب حفظهما؛ لا يمكن استرجاع الرمز المفقود، ولا نخزن نسخته الأصلية في قاعدة البيانات.
- الإدارة تبحث وتصفّي أحدث ١٠٠٠ طلب، وتعرض المرفقات وتغير الحالة وتكتب ردًا يظهر للعميل عند المتابعة.
- التحديث يدوي. لا توجد رسائل واتساب أو إشعارات خارجية في هذه النسخة.

## البيانات والنشر

التخزين الافتراضي SQLite والمرفقات داخل `DATA_DIR` (افتراضيًا `./data`)، ويتطلب هذا الوضع قرصًا دائمًا. يمكن بدلًا منه ضبط `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` مع `ADMIN_PASSWORD` لتخزين قاعدة البيانات والمرفقات في Supabase وتشغيل التطبيق على استضافة ذات قرص مؤقت. استضافة الملفات الثابتة وحدها لا تكفي. لا تفترض بقاء الملفات على الخدمات ذات القرص المؤقت. تشغيل نسخة خادم واحدة هو الوضع المدعوم؛ الجلسات وحدود الإرسال في الذاكرة وتُصفّر عند إعادة التشغيل.

قبل إتاحته للعملاء:

1. اختر استضافة Node.js 24 ذات تخزين دائم، واربط `DATA_DIR` به.
2. اضبط كلمة مرور قوية عبر `ADMIN_PASSWORD`، و`APP_ORIGIN` على أصل الرابط العام مثل `https://requests.example.com` بدون مسار أو شرطة أخيرة، و`COOKIE_SECURE=true`.
3. فعّل HTTPS عبر الاستضافة أو الوكيل العكسي. ملف `.env.example` للتوثيق؛ التطبيق لا يقرأ ملفات `.env` تلقائيًا.
4. اختبر إرسال طلب ودخول الإدارة وتحديث الحالة وقراءة المرفق على الاستضافة الفعلية.
5. خذ نسخًا احتياطية دورية لمجلد البيانات. للنسخ اليدوي المتسق أوقف الخادم، انسخ مجلد البيانات كاملًا إلى مكان آمن ثم أعد التشغيل. اختبر الاستعادة قبل الاعتماد عليها.

المرفقات لا تظهر إلا للإدارة؛ المتابعة لا تكشف الملاحظات أو المرفقات. توجد حماية من الإرسال المتكرر وكشف ملفات ذات نوع مخالف، لكن الإطلاق واسع النطاق يحتاج ضبط الحدود والتخزين وسياسة الاحتفاظ بالبيانات حسب الاستخدام. خلف وكيل موثوق يستبدل `X-Forwarded-For` يمكن تفعيل `TRUST_PROXY=true` لحساب الحدود لكل عميل. لا تفعّله عند كشف التطبيق مباشرة. لا تستخدم ملفًا حساسًا كمرفق، ولا تودع قاعدة البيانات أو كلمة المرور في Git.

لم يُنشر الموقع على الإنترنت بعد، ولم تُختبر استعادة بيئة جديدة. مجانية الاستضافة ومدتها تعتمد على مزود الخدمة.

## حزمة النشر

ملفات Docker وCompose مع HTTPS تلقائي وقرص دائم ودليل نسخ واستعادة متوفرة في [deploy/README.md](deploy/README.md). يحتاج تنفيذ النشر حساب استضافة أو سيرفر ونطاقًا فعليًا.

## النشر بخطط مجانية

اتبع [دليل Render وSupabase](deploy/FREE-HOSTING.md). أضيف دعم التخزين البعيد مع الحفاظ على SQLite المحلي. الحسابات والقيم الآمنة لم تُضبط بعد؛ لم يُختبر اتصال حقيقي بـ Supabase أو نشر Render.
